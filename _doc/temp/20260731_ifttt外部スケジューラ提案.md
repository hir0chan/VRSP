# 【保留】IFTTT による外部スケジューラ化の提案

日付: 2026-07-31
状態: **保留**(ユーザー判断待ち。まずは cron 分オフセット `3,18,33,48` の効果を観察)

## 背景

GitHub Actions の `schedule`(cron)はベストエフォートで、15分毎指定に対し実際は数時間おきにしか発火しない事象が発生(2026-07-31 確認: 8時間で2回のみ。実行された run はすべて成功しており、パイプライン自体は健全)。対策1として cron を混雑時間帯を避けた `3,18,33,48 * * * *` に変更済み。本提案は対策2(より確実な外部起動)。

## 提案内容

ユーザー契約済みの IFTTT から、GitHub の `workflow_dispatch` を定期的に POST で叩く。**リポジトリ側の改修は不要**(workflow_dispatch トリガーは実装済み)。

IFTTT の Webhooks「Make a web request」アクションは POST・カスタムヘッダー(Authorization 含む)対応を確認済み。
注意: GitHub のワークフロー起動は GET 不可(POST + Authorization ヘッダー必須)。

## セットアップ手順

### ① PAT の作成(hir0chan アカウントで)

1. GitHub → Settings → Developer settings → Fine-grained personal access tokens → Generate new token
2. Repository access: **Only select repositories → hir0chan/VRSP**
3. Permissions → Repository permissions → **Actions: Read and write** のみ
4. 有効期限は任意(失効時は IFTTT 側の差し替えが必要)

### ② IFTTT アプレット(15分間隔には4つ必要 — 時刻トリガーは「毎時◯分」が最小粒度)

- **If**: Date & Time → Every hour at → 05分 / 20分 / 35分 / 50分(cron の 3,18,33,48 分と重複しないようオフセット)
- **Then**: Webhooks → Make a web request

| 項目 | 値 |
|---|---|
| URL | `https://api.github.com/repos/hir0chan/VRSP/actions/workflows/update.yml/dispatches` |
| Method | `POST` |
| Content Type | `application/json` |
| Additional Headers | `Authorization: Bearer <PAT>` (改行) `Accept: application/vnd.github+json` |
| Body | `{"ref":"main"}` |

まず1アプレットで1発火を確認(`gh run list` に workflow_dispatch が現れる)→ 残り3つを複製、の順が安全。

## 留意点

- 既存 cron との併存は可(workflow の `concurrency` により同時発火しても競合しない)。安定後に cron を外す選択も可
- PAT は IFTTT に預ける形になるが、権限を当該リポジトリの Actions 起動のみに絞ってあり、漏洩時の影響範囲は限定的
- 代替候補: cron-job.org 等の無料スケジューラでも同じ構成が可能(IFTTT 解約時の乗り換え先)
