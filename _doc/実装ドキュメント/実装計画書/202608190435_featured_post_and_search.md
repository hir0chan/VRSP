## 1. 背景・目的

現行の X 定期ポスト(新規 live 配信者名の列挙)は誘引力に欠けるというユーザー判断。「配信中から1件をランダムに紹介し、そのままその配信に辿り着けるパラメータ付きサイトリンクを貼る」形式へ刷新する。あわせてサイトに自由入力の絞り込みフィールドを追加し、`?q=` パラメータで入力済み状態のディープリンクを可能にする。

ユーザー合意済み事項(2026-08-19):

| 論点 | 合意 |
|---|---|
| リンク先 | サイト+パラメータ(`https://vcha-antenna.com/?q=配信者名`)。動画直リンクはしない |
| 選出・投稿条件 | 配信中の日本語配信**全体**から1件ランダム。live が1件以上あれば2時間毎に毎回投稿(「新規あり」条件は廃止)。同一配信の連続選出は避ける |
| パラメータ | `?q=配信者名`(検索フィールドへの入力済み状態) |
| 文面 | 「👉️ 今おすすめのVRChat配信は?」+概要+リンク+live総数+既存タグ。細部は変更可 |

## 3. 確定仕様

### 3.1 サイト: 検索フィールド

| 項目 | 決定内容 |
|---|---|
| UI | 既存 `.filter-controls`(HomePage.astro)にテキスト入力を1つ追加。placeholder は i18n(ja「配信者・タイトルで絞り込み」/ en 相当)。クリアは入力を空にするだけ(専用ボタンなし。`type="search"` のネイティブクリアに任せる) |
| 対象・一致 | 各カードの「タイトル+配信者名」への部分一致。大文字小文字を区別しない(`toLowerCase` 同士)。正規化はそれ以上しない(かな/カナ変換等はしない。最も単純な案) |
| データ供給 | `StreamCard.astro` に `data-search={`${stream.title} ${stream.streamer.name}`.toLowerCase()}` を追加 |
| 適用機構 | 既存のプラットフォーム/日本語フィルタ(html 属性+CSS)とは独立に、JS がカードへ `data-search-miss` 属性を付与し CSS `[data-search-miss] { display: none }` で非表示。既存フィルタとは AND で効く |
| 表示可否の判定 | CSS の計算結果(`getComputedStyle` や `:has()`)に**依存しない**。「カードの `data-ja` / `data-platform` / `data-search` 属性+ルートのフィルタ状態+検索語」から表示可否を返す**純関数**として実装し、DOM 反映はその結果を属性に書くだけにする(既存の日付グループ非表示 CSS は `:has()` で DOM 存在を見ており `data-search-miss` を認識しないため) |
| 空グループ | 検索対象セクションに専用属性 `data-stream-section` を付与(コミュニティ枠・元から空で `.empty-state` のみのセクションは対象外)。再計算は毎回「全 `data-search-empty` を解除 → 判定 → 付与」の順で行い、检索語が空なら `data-search-miss` / `data-search-empty` をすべて解除して終了。全対象セクションが空のときのみ「該当なし」メッセージを表示 |
| 再計算のトリガ | 検索欄の `input` に加え、**既存のプラットフォーム/日本語フィルタの `change` 後にも空判定を再実行**する(既存イベントはルート属性を変えるだけで検索側と連動しないため)。debounce なし(件数は高々数百枚で不要) |
| アクセシビリティ | placeholder だけでなく i18n された `aria-label`(または視覚的に隠した `<label>`)を付与 |
| XSS 対策(実装規則) | `q` およびタイトル由来文字列を `innerHTML` / `insertAdjacentHTML` に渡さない。値の設定は `HTMLInputElement.value`、文言表示は `textContent` のみ。`?q="><img src=x onerror=...>` と引用符入りタイトルを検証に含める(Astro の属性エスケープ+この規則で反射 XSS は成立しない) |
| ?q= パラメータ | ロード時に `URLSearchParams` から `q` を読み、入力欄へ設定して適用。**localStorage には保存しない**(ディープリンクであって嗜好設定ではない)。入力変更時も URL は書き換えない(最も単純な案)。日英ページの言語切替リンクでは `q` を**引き継がない**(切替後は全件表示) |
| 選ばれた配信が終了していた場合 | 検索結果 0 件+「該当なし」メッセージになるのみ(特別扱いしない。ユーザーが入力を消せば全件に戻る) |
| JS の置き場所 | 既存フィルタ処理と同じ Layout.astro のインラインスクリプトに追記。`.filter-controls` の `hidden` 解除(JS 有効時のみ表示)の既存パターンに従う |

### 3.2 X ポスト刷新(scripts/digest.ts)

| 項目 | 決定内容 |
|---|---|
| サニタイズの分離 | 文字の無害化と長さ制限を分離する。`sanitizePostText(text)`: 制御文字(`\p{Cc}`)+**書式制御文字(`\p{Cf}`。bidi 制御等)**→空白・連続空白縮約、`@`/`#`(全角含む)・ドット類→中黒、**URL 風トークン(`https?://` 等)の無害化**を行う長さ制限なしの共通関数。配信者名はその結果を従来どおり重み40で切り詰め、タイトルは固定文・配信者名・URL・タグを差し引いた**残余予算で最後に**切り詰める(+「…」) |
| サニタイズ後が空の場合 | タイトルが空 → その配信を選出対象から外して再抽選(全滅なら配信者名のみの退避文面)。配信者名が空 → タイトルのみの文面(`?q=` リンクは張れないためサイトトップへのリンクにする) |
| 選出 | `status === "live" && isJapanese === true` の全件から Node の `Math.random` で1件(乱数は `randomFn` 注入でテスト可能に)。**前回選出(state の `lastFeaturedId`)は候補が2件以上あるとき除外**して連続を回避。`lastFeaturedId` は `${platform ?? "youtube"}:${stream.id}` の複合キー(`streamKey` ヘルパーとして現 `announcedKey` を改名して残す。生 id はプラットフォーム間で一意性の保証がないため) |
| 投稿条件 | 前回投稿から120分以上経過 かつ live JP が1件以上。「新規 live あり」条件・announced 集合・ベースライン初期化は**廃止** |
| 状態ファイル | `digest.json` を `{ lastPostedAt?: string, lastFeaturedId?: string }` に簡素化。旧形式の `announced` は読込時に**内容・型を検証せず無視**して次回書込で消える。`lastFeaturedId` は文字列以外なら不正として非0終了。lastPostedAt の妥当性検証・未来値規則・原子的書込は現行のまま。**state ファイルなしの初回は、live があれば即投稿**(ベースライン概念の廃止。旧実装の `"initialized"` 分岐は削除) |
| URL の重み | 本文**途中**に現れる `https://vcha-antenna.com/?q=...` の行を23固定で計算する(t.co 短縮のため実 URL 長に依存しない)。長大な配信者名で URL が長くなっても重みは23のまま |
| リンク | `https://vcha-antenna.com/?q=${encodeURIComponent(配信者名)}`(名前は**サニタイズ前の生の値**をエンコード。サイト側の検索対象は表示名なので生値が正しく一致する)。X 上では t.co 化されるため重みは23固定 |
| 文字数 | 重み付き280以内。タイトルは残余予算内で切り詰め(+「…」)。配信者名は既存の40上限。固定文・URL・タグを引いた残りをタイトルに配分する |
| 既存機構の維持 | 両キー(IFTTT/YouTube)ガード・120分判定・postToIfttt・原子的書込・--dry-run・エラーメッセージの秘匿はそのまま |
| 不要コードの削除 | `selectNewLives` / `pruneAnnounced` / `announcedKey` / `AnnouncedEntry` と関連テストを削除(過剰な後方互換は持たない)。`countLiveJapanese` は続投 |

### 文面テンプレート

```

{タイトル}({配信者名})
{https://vcha-antenna.com/?q=配信者名}

```

### 成立性の根拠(調査済み)

- カードは `data-ja` / `data-platform` 属性+CSS で絞り込む構造(`StreamCard.astro:27`、global.css に45箇所の列挙)。テキスト検索は任意文字列のため CSS では表現できず、JS 付与の属性で独立に制御する設計が既存構造と干渉しない
- `.filter-controls` は `hidden` で出力され JS が解除する既存パターンあり(JS 無効環境では検索欄も出ない=現行フィルタと同じ縮退)
- digest.json の形式変更は読み手が digest.ts のみであることを確認済み(サイト・update.ts は参照しない)
- ポスト頻度は変わらず最大12件/日(月360件)。IFTTT 制限評価は従来のまま有効

- `scripts/models.ts`: `DigestState` を新形式へ、`AnnouncedEntry` 削除
- `test/digest.test.ts`: 新仕様(選出・連続回避・タイトル切り詰め・旧 state 読込互換・毎回投稿条件)に全面改訂
- **検索の表示可否判定は純関数として `src/lib/` に切り出し、必ず自動テスト対象にする**(例: `src/lib/search.ts` の `matchesSearch(searchText, query)` と `isCardVisible(card条件, filter状態)` 相当)。DOM への属性反映のみ dev サーバーで手動確認する

## 5. 検証計画

1. **正常系**: `npm test`・`npm run check`・`npm run build` 全パス。dry-run で新テンプレートの本文・?q= リンク・280以内を確認
2. **digest 異常系・境界**:
   - live 0件 → スキップ。live 1件のみ → lastFeaturedId と同一でも選出(除外は候補2件以上のとき)
   - **初回(state ファイルなし)+live あり → 即投稿し新形式 state 作成。state なし+live なし → スキップ**
   - 旧形式 digest.json(`announced` あり。内容が不正型でも)の読込が成功し、新形式で書き戻されること。`lastFeaturedId` が文字列以外 → 非0終了
   - 長大タイトル(絵文字含む)の切り詰めで280以内。**長大な配信者名で URL が長くても URL 部分は23重みで計算されること(本文途中 URL の重み計算テスト)**
   - 悪意あるタイトル・配信者名(`@`/`#`(全角含む)/URL 風文字列/改行/`\p{Cf}` bidi 制御/引用符)のサニタイズ。サニタイズ後が空のケース(タイトル空→再抽選、名前空→トップリンク退避)
   - lastPostedAt 検証・キー欠落スキップ・POST 失敗時 state 無変更の回帰
3. **検索ロジック(自動テスト)**: platform × 日本語のみ × 検索語の全組み合わせで表示可否が正しいこと。検索解除で全解除。日付グループに複数プラットフォーム混在時の空判定。「一致カードはあるが既存フィルタで隠れる」ケース
4. **サイト(dev サーバーで手動)**: 検索欄の即時絞り込み(タイトル一致・配信者名一致・大文字小文字)、既存フィルタとの AND、**「検索→プラットフォーム変更→日本語切替→検索クリア」の順序操作**、空グループ非表示と「該当なし」(コミュニティ枠が誤って隠れないこと)、`?q=◯◯` 直アクセスで入力済み+絞り込み済み、`?q="><img src=x onerror=...>` で XSS が成立しないこと、`/en/?q=...` の初期適用と英語 placeholder/該当なし文言、言語切替で `q` が引き継がれないこと、JS 無効時に検索欄非表示
5. **回帰**: 既存フィルタ(プラットフォーム・日本語のみ・localStorage 復元。日本語ページで保存した設定が英語ページでも復元される挙動含む)が無変更で動作。classify・thumbnail 等の既存テスト全パス

## 6. 影響範囲・リスク

- digest.ts は文面・選出ロジックの書き換え(投稿経路・状態管理の骨格は不変)。サイトは表示層への追加のみでデータ取得層は無変更
- ランダム紹介のため、配信者側から見て「紹介された/されない」の偏りが出る(乱数なので長期的には均される。苦情があれば blocklist で個別除外可能)
- 紹介した配信がポスト閲覧時点で終了しているケースは構造上避けられない(サイト側は「該当なし」表示で縮退)
- 旧ポスト形式の「新規スタート告知」機能は消える(ユーザー合意済み)
