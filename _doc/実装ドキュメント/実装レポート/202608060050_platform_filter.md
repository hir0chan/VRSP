## 概要

Twitch 対応で初期表示コンテンツが増えたことを受け、トップページに **プラットフォームフィルタ(すべて / YouTube / Twitch)** を追加した。既存「日本語のみ」トグルと同じ機構(カード属性 + `<html>` 属性 + CSS + localStorage)で実装し、依存追加・データ層変更はゼロ。

## 実装内容

- **UI**: ヒーロー直下の `.filter-controls` に角丸ピル型セグメントコントロールを設置。選択中は `--accent-deep` 地に白文字(コントラスト規則準拠)。fieldset + 視覚的非表示の legend「プラットフォーム」で支援技術にグループ用途を提示。JS 無効時はコントロール自体が表示されない(既存と同じ)
- **フィルタ機構**: カードの `data-platform` × ルートの `data-platform-filter` を CSS で照合。「日本語のみ」とは属性が独立しているため AND 併用が自動成立
- **空日付グループ非表示**: フィルタ状態の組み合わせ5ルールの `:has()` 列挙で「表示カード0のグループ」を丸ごと非表示(併用時に別々のカードが各条件を満たすケースも正しく消えることを確認済み)
- **永続化**: localStorage `vrsp-platform`。head 内同期 script で描画前復元(ちらつきなし)。不正値は「すべて」扱い、storage 例外時もページ内動作は維持
- **レスポンシブ**: `.filter-controls` に flex-wrap / gap を追加し 320px でも破綻なし

計画書 §9 の検証結果表を参照。`npm run check` 0 errors・`npm test` 全パス・`npm run build` 成功に加え、実データ(YouTube 69件 / Twitch 34件)での切替・復元・異常系・境界・回帰を chrome-devtools で確認した。

## ユーザーに確認したい事項

- 件数バッジ(NOW ON LIVE の「49」など)はフィルタ適用後も全件数のままです(日本語のみトグル導入時の割り切りを踏襲)。フィルタ連動に変える場合は別途小改修で対応可能です

## 追記1(2026-08-06 ユーザーフィードバック対応)

1. **フィルタのトグルが押しても反応なしの修正**: 原因は `.filter-controls` が負マージンでヒーロー(`position: relative; z-index: 0`)の領域に重なっており、スタッキングの解釈によってはヒーローがクリックを奪う構造だったこと(Chrome の hit-test では偶然ラベルが勝つが、hero の z-index 変動で再現を確認)。`.filter-controls` に `position: relative; z-index: 1` を付与し前面を保証した
2. **セグメントへアイコン併記**: YouTube / Twitch のラベルに公式アイコンの `currentColor` 単色版をインライン SVG で追加。非選択時はブランド色(#FF0000 / #9146FF)、選択時はラベルの白文字を継承(単色白は両社ガイドラインとも許容)
3. **「日本語のみ」デフォルト ON**: `<html>` に `data-ja-only` を静的レンダリングし(JS 無効環境でもデフォルト ON)、明示的に OFF にした場合のみ localStorage に `"0"` を保存して head script で属性を外す方式に反転。旧形式 `"1"` 保存ユーザーは ON のまま(互換)

検証: `npm run check` 0 errors・`npm test` 44 全パス・`npm run build` 成功。ブラウザで初期 ON(非日本語 0件表示)・OFF 保存 `"0"` とリロード復元・旧値 `"1"` の互換・アイコン色(非選択ブランド色/選択白)・hero の z-index を変動させてもラベルがクリック可能なことを確認した。
