## 1. 背景・目的

サイトを `https://hir0chan.github.io/VRSP/` から独自ドメイン `https://vcha-antenna.com/` へ移行する。ドメインは Cloudflare Registrar で取得済み・ゾーン active。DNS 設定済み(apex / www とも CNAME `hir0chan.github.io`、DNS only、apex は Cloudflare の CNAME 平坦化)。

GitHub Pages のカスタムドメインではサイトが**ドメイン直下**で配信されるため、`/VRSP/` サブパス前提の `base` 設定を変更する必要がある。

## 3. 確定仕様

| 項目 | 決定内容 |
|---|---|
| 新 URL | `https://vcha-antenna.com/`(ja)/ `https://vcha-antenna.com/en/`(en)。`www` は GitHub Pages が apex へリダイレクト |
| astro.config.mjs | `site: "https://vcha-antenna.com"`、`base: "/"` |
| Layout.astro | フォールバック `Astro.site ?? "https://hir0chan.github.io"` → `?? "https://vcha-antenna.com"`(canonical / OGP / hreflang は既存ロジックのまま site+BASE_URL から導出) |
| scripts/digest.ts | `SITE_URL = "https://vcha-antenna.com/"`(重み23は不変) |
| test/digest.test.ts | テスト側の `SITE_URL` 複製と本文末尾の URL 正規表現を新ドメインに更新 |
| public/sitemap.xml | `/` と `/en/` の2エントリを新ドメインへ更新(レビューで発覚した変更漏れ)。移行後に Search Console の新ドメインプロパティへ sitemap を再登録(ユーザー作業・任意) |
| ドキュメント | README(公開 URL・dev URL)、CLAUDE.md(公開 URL・dev URL・概要行の `/VRSP/`・`/VRSP/en/` ロケール表記)を更新。dev サーバーは `http://localhost:4321/` になる |
| テスト追加 | `test/thumbnail.test.ts` に base `/` の回帰ケースを追加(既存の `/VRSP/` ケースは汎用性確認として残す) |
| GitHub Pages 設定 | `gh api -X PUT repos/hir0chan/VRSP/pages -f cname=vcha-antenna.com` でカスタムドメイン設定 → 証明書発行完了を待って `gh api -X PUT repos/hir0chan/VRSP/pages -F https_enforced=true`(真偽値のため -F 型付き指定)。Actions デプロイ(actions/deploy-pages)では設定はリポジトリ設定に保持されるため public/CNAME ファイルは不要 |
| 旧 URL | GitHub Pages が `hir0chan.github.io/VRSP/*` → `https://vcha-antenna.com/*` へ自動リダイレクト(X 投稿済みリンクは切れない) |
| 切替順序 | **事前ゲート**: ①変更後コードでローカルの test / check / build を完了 ②`gh run list` で queued / in-progress の実行がないことを確認 ③cron 時刻(毎時 03/18/33/48 分)の直前を避け、cron 完了直後の窓で実施。**切替**: ④コード変更をコミット(push はまだしない)⑤Pages カスタムドメイン設定 ⑥直後に push し、Actions 完了まで監視。⑤〜デプロイ完了の間は新ドメインで旧 base のビルドが配信されリンク切れする(所要は「Pages 設定から新 artifact のデプロイ完了まで。CI の全ステップ+キュー待ちを含み、cron 競合時は延びる」)。**ロールバック**: デプロイ失敗時は `gh api -X PUT repos/hir0chan/VRSP/pages -F cname=null` でカスタムドメインを解除し旧 URL 配信に戻す |
| 変更しないもの | データ取得層(digest.ts の定数以外)・分類/サムネ解決ロジック(`thumbnail.ts` は BASE_URL 前置のため `base: "/"` でもそのまま正しく動く)・update.yml・niconico.ts の USER_AGENT(GitHub リポジトリ URL 表記であり サイト URL ではない) |

### 成立性の根拠(調査済み)

- 直書き URL は `astro.config.mjs`・`Layout.astro:16`・`scripts/digest.ts:14`・`test/digest.test.ts`(複製定数+正規表現)・`public/sitemap.xml`(初回 grep の対象漏れ。codex レビューで発見)・README・CLAUDE.md と確認。表示層は全て `Astro.site` / `import.meta.env.BASE_URL` 経由
- Cloudflare ゾーン active・トークン検証済み・CNAME 2件作成済み(2026-08-16 実施)
- Pages は Actions デプロイのため、カスタムドメインは Pages 設定(API)にのみ保存され、ビルド成果物への CNAME 同梱は不要

## 5. 検証計画

1. **ビルド検証**: `npm test`・`npm run check`・`npm run build` 全パス。`dist/index.html` の canonical / og:url / hreflang が `https://vcha-antenna.com/` 系になっていること、アセット参照が `/` 直下であること、`dist/sitemap.xml` が新ドメインになっていること
2. **切替後の実機確認**: `https://vcha-antenna.com/` と `/en/` が 200・HTTPS 有効・サムネ/CSS/OGP 画像が表示されること。リダイレクトは深めに確認: `hir0chan.github.io/VRSP/` → `/`、`/VRSP/en/` → `/en/`、クエリ付き URL、リダイレクト先に旧パス `/VRSP/` が残っていないこと。`www.vcha-antenna.com` → apex リダイレクト
3. **digest 回帰**: 次回投稿の本文 URL が新ドメインになること(dry-run で事前確認)
4. **回帰**: 既存テスト全パス

## 6. 影響範囲・リスク

- 変更は設定値・定数・ドキュメントのみでロジック変更なし
- 切替中(Pages 設定から新 artifact のデプロイ完了まで。CI・キュー状況により変動)、新ドメイン側で旧 base のリンク切れが起こりうる(許容)
- GitHub Pages の証明書発行に数分〜かかる場合があり、その間 HTTPS 強制は設定できない(発行完了を待って設定)
- Cloudflare の proxy は無効(DNS only)のため、証明書は GitHub(Let's Encrypt)発行。将来 proxy を有効化する場合は別途検討

## 9. 実施結果(2026-08-16 実装・検証完了)
